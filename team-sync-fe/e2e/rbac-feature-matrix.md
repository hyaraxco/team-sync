# RBAC route and API source inventory

Source snapshot: checked-in Vue route metadata, Laravel `routes/api.php`, `PermissionSeeder`, `RolePermissionSeeder`, and current E2E specs. This is a source inventory, not evidence that listed allow/deny outcomes work at runtime. `allow`/`deny` mean the role permission allowlist includes/excludes the FE guard permission(s); `unverified` means no permission-based source outcome can be derived. Superadmin is source-derived `allow` for every declared FE permission because `superadmin->syncPermissions(Permission::all())` includes permissions seeded by `PermissionSeeder`; the runtime fixture exists (`E2ESuperadminSeeder`, `superadmin@teamsync.com`) and `role-navigation.spec.ts` proves Superadmin login plus access to the staff directory and settings, while the remaining Superadmin cells stay source-only. API behavior is marked unverified unless declarations show an explicit authorization boundary. N/A means the role is not an actor for the route's purpose; it does not imply a tested denial.

Existing specs below are evidence of the named UI/API scenario only, never blanket proof for a family. `role-navigation.spec.ts`/`role-button-matrix.spec.ts` predominantly establish navigation/button visibility or client redirects, not API authorization.
